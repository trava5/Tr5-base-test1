# Purpose

This is the first implementation contract to run end-to-end through the Tr5-base pipeline for this cloned project. Its purpose is not the file's content itself but proving out the architect → reviewer → programmer flow on the smallest possible real case (PRINCIPLES.md P11), leaving a durable, human-readable marker in the repository that this milestone happened.

---

# Intent

The implementation deliberately does only one thing: create a single small Markdown file with a short welcome note. It deliberately does not touch any framework layer file (agents/*.py, chat_architect.py), any governance document (AGENTS.md, PRINCIPLES.md, ROLE.md, COMMANDS.md), or any memory file. It relates to the existing architecture only through project/README.md, which already states that project/ is empty until the first contract is implemented (project/README.md, 'Current limitations') and that project/ is where every implementation contract's actual code changes land.

This change adds the first file alongside that README.md.

# Inputs

The existing project/README.md, which already documents project/'s purpose and current empty state; no other module, API, or data is used.

# Outputs

A new file project/HELLO.md containing a short, single-paragraph welcome note explaining that this is the first test contract run on a project cloned from Tr5-base. No other file is created or modified.

### Round 1 — 2026-08-18T07:27:08+02:00 — Verdict: CHANGES_REQUESTED — Reviewer: `reviewer`

Checked Purpose/Intent against P11/P15 (validate a new structural decision — the architect→reviewer→programmer pipeline — on the smallest possible real case): the contract explicitly frames itself as a minimal pipeline-proving artifact rather than a premature abstraction; this is a legitimate, non-speculative architectural need and matches P1 (build today's need, not tomorrow's assumption). Checked Functional Requirements: the single point has one clear, mechanically verifiable acceptance criterion set (file exists, exactly one paragraph, states it is the first test contract on a Tr5-base clone, no other file touched) — actionable without further questions. Checked Out of Scope: explicit about not touching project/README.md, no code/script/executable logic, nothing outside project/, no references elsewhere — no edge case left for the programmer to guess. Checked Current State against the actual repository: project/ contains only README.md today, and project/README.md's own 'Current limitations' section ('Empty until the first contract is implemented') matches the contract's claim — verified directly, not taken on faith. Checked scope/permissions: writing project/HELLO.md is within `project/`, the programmer's default write scope per AGENTS.md/ADR-022, no destructive command or access beyond the `edit` permission profile is required. Checked risk_level per Tr5-base decision 7: no real credentials/API keys, no real external-system calls, no native/hardware libraries, no personal/real data — 'standard' is correctly assigned and does not need escalation. Checked backward compatibility: not applicable, purely additive, no existing behavior touched. Checked the naming convention (AGENTS.md 'Naming convention', ADR-008) against the proposed filename `project/HELLO.md`: AGENTS.md states 'Document .md files that carry a rule, role, state, or contract (not free-form text): UPPERCASE_WITH_UNDERSCORES.md' — explicitly excluding free-form text from the UPPERCASE bucket, with README.md called out as the exception because it carries structured state per the ADR-015 README standard. The contract's own Point 1 explicitly defines the file's content as 'a single short paragraph (no headings, no lists)' — a textbook case of the free-form text the convention excludes from UPPERCASE naming. As written, `project/HELLO.md` (and its acceptance criteria, which reference that exact path) conflicts with this rule and should be `project/hello.md` (or similarly named in lowercase_with_underscores). This is a fixable requirements-level issue, not an architecturally wrong request — the file's purpose, content, and scope are all otherwise sound.
